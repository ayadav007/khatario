# Store theme engine and Studio 2: design

Date: 2026-10-29
Status: approved in chat, awaiting written review
Companion spec: `2026-10-29-store-shopping-features-design.md` (project C, shopper features; built in parallel)

## 1. Goal

Give Khatario merchants a Shopify-grade online store design experience:

- every storefront page (home, product, catalog, custom pages) is built from **sections that contain blocks**;
- a **theme library** with one live theme and draft themes, preview links and **version history**;
- **Studio 2**, an editor in the style of Shopify's theme editor: page switcher, section/block tree, live preview with click-to-select, drag to reorder, undo/redo, autosave, publish;
- all four existing themes (Studio, Quick, Premium Grocery, Khatario) rebuilt as **presets of one engine**, with existing stores migrated automatically and looking the same.

### Decisions taken with the user

| Topic | Decision |
|---|---|
| Priority | Merchant design (this spec) and shopper features (project C) in parallel |
| Existing themes | All four rebuilt as presets; automatic migration |
| Editable pages in v1 | Home, product, catalog/category, custom pages |
| Editor v1 | Click and drag editing, undo/redo, theme library, version history |
| Code access | Scoped custom CSS (as today) plus a sanitised Custom HTML block; no template code |
| Approach | Own schema-driven engine (Shopify Online Store 2.0 model); `@dnd-kit` for drag and drop; no third-party page builder |

### Assumptions (not stated by the user)

- Checkout stays fixed (as on Shopify). The cart drawer has theme settings but no sections.
- Each store's brand colour remains its default accent.
- No migration runs outside `kh_phase2_test` until the user says so.
- The existing policy/about/contact/khata/account/wishlist routes keep their current pages.

### Out of scope

- Theme code editing (Liquid-style templates, scripts).
- Third-party app blocks or a theme marketplace.
- Alternate templates per product or category (one product template, one catalog template).
- Scheduled publishing.
- Shopper features themselves (gallery, filters, reviews, search suggestions, abandoned cart): project C builds them; this engine wraps them as sections in M3.

## 2. Data model and storage

```
Theme
  id, name, role: 'live' | 'draft', preset: 'studio' | 'quick' | 'grocery' | 'khatario' | 'blank'
  settings        global: colour_schemes[], typography, buttons, cards, spacing, cart, phone_kit,
                  social, favicon, custom_css
  header_group    { order: string[], sections: Record<id, Section> }   // announcement, header
  footer_group    { order: string[], sections: Record<id, Section> }   // footer
  templates
    home          Template
    product       Template      // one template for all products
    catalog       Template      // /catalog and /catalog/[category]
    'page.<handle>'  Template & { title, seo_title, seo_description }

Template  { order: string[], sections: Record<id, Section> }
Section   { type, settings, blocks: Record<id, Block>, block_order: string[],
            disabled?, color_scheme?, css_class?, custom_css? }
Block     { type, settings, disabled? }
```

IDs are short random strings generated by the editor and re-validated on save (`[a-z0-9_-]{1,32}`).

### Tables (migration `4xx_store_themes.sql`)

- `store_themes`: `id uuid pk`, `business_id` FK, `name varchar(60)`, `role varchar(8)` (`live`/`draft`), `preset varchar(16)`, `data jsonb`, `created_at`, `updated_at`, `updated_by`.
  - Partial unique index: one `role = 'live'` row per `business_id`.
  - At most 20 themes per business (checked in the API).
- `store_theme_versions`: `id`, `theme_id` FK (cascade), `business_id`, `data jsonb`, `published_at`, `published_by`. One row per publish; the API keeps the newest 30 per business.
- `business_settings.store_engine boolean default false`: per-store rollout flag.
- `business_settings.store_theme` stays for one release as a read-only fallback, then is dropped in M6.

### Rules

- Autosave writes the draft (or live) theme being edited. Editing the live theme directly is not allowed: "Customise" on the live theme first creates or reuses a working draft, and "Publish" swaps roles in one transaction and writes a version row.
- Rollback copies a version's `data` into a new draft theme.
- Server-side limits on every save: 25 sections per template, 50 blocks per section, 30 custom pages, 512 KB serialised theme.
- Every section, block and setting is sanitised against its schema (section 3): unknown keys dropped, values clamped, unknown section/block types dropped.
- `business_id`, `updated_by` and `published_by` always come from the session, never the client.
- Preview: `?preview_theme=<id>&token=<signed>` renders a draft. Tokens are HMAC-signed with business id, theme id and expiry (editor tokens 2 h, shared preview links 7 days), reusing today's `td` token approach.

## 3. Section schemas and registry

Each section type lives in `components/store/engine/sections/<type>/`:

- `schema.ts`: plain serialisable data, importable on the server;
- `Section.tsx`: the storefront component (server component where possible).

`lib/store/engine/registry.ts` maps type → schema (server-safe) and `components/store/engine/registry.tsx` maps type → component.

```ts
interface SectionSchema {
  type: string;
  name: string;
  category: 'Header and footer' | 'Banners' | 'Products' | 'Text' | 'Media' | 'Social proof' | 'Product page' | 'Catalog' | 'Advanced';
  templates: Array<'home' | 'product' | 'catalog' | 'page' | 'header' | 'footer'>;
  limit?: number;                 // per template
  settings: SettingSchema[];
  blocks?: BlockSchema[];
  max_blocks?: number;
  presets: Array<{ name: string; settings?: Record<string, unknown>; blocks?: Array<{ type: string; settings?: Record<string, unknown> }> }>;
  data?: (settings: Record<string, unknown>) => SectionDataRequest;   // server data needs
}
```

Setting types: `text`, `textarea`, `richtext` (allow-listed tags: p, strong, em, a, ul, ol, li, br, h2–h4), `number`, `range`, `checkbox`, `select`, `radio`, `color`, `color_scheme`, `image`, `video_url`, `url` (internal link picker or https URL), `product`, `product_list`, `category`, `category_list`, `icon`, `font`, `html`, `header` (form heading only, no value).

`lib/store/engine/sanitize.ts` sanitises any theme from the registry. It replaces the hand-written `RULES` map in `lib/store/studio-sections.ts`.

Custom HTML (`html` setting, Custom HTML section): sanitised server-side on save and again at render. No `script`, `style` elements with `@import`, event-handler attributes, `javascript:` URLs, `object`/`embed`/`form`. `iframe` only for `youtube.com/embed`, `youtube-nocookie.com/embed`, `google.com/maps/embed`, with `sandbox` and `loading="lazy"` forced. Max 20 KB.

### Launch catalog

- Header and footer groups: announcement bar, header (logo, menu, search, account, cart, delivery ETA), footer (link columns, social, payment icons, newsletter block).
- Home and pages: slideshow, image banner, image with text, rich text, multicolumn (USPs/features), marquee, featured products, product rail (sources: featured, new, bestsellers, discounted, category, price cap), collection list, category grid, testimonials, logo list, video, FAQ (collapsible), newsletter, countdown/offer, custom HTML, spacer.
- Product template: product info (blocks: title, price, variant picker, quantity, buy buttons, description, collapsible tab, delivery estimate, share, custom text), product gallery, related products, recently viewed, reviews.
- Catalog template: catalog banner, filters + product grid, promo tile.

Product-page and catalog sections wrap project C's components when they land. Until then they wrap the current product view and catalog grid.

### Colour schemes

Theme settings hold up to 6 schemes: `background, text, accent, button, button_text, border, card`. Each section has a `color_scheme` setting. The renderer applies the scheme as CSS variables on the section root (`--c-bg`, `--c-text`, `--c-accent`, `--c-btn`, `--c-btn-text`, `--c-border`, `--c-card`), and the existing `--primary` keeps mapping to scheme 1's accent for compatibility with merchant CSS.

### Presets

`lib/store/engine/presets/{studio,quick,grocery,khatario,blank}.ts` each export a full starting theme (settings plus all templates). Each preset also ships a CSS layer (`components/store/engine/presets/<preset>.css`, scoped by a root class) that gives shared sections that preset's look, so Grocery's category tiles stay Grocery's. The phone kit becomes engine behaviour switched by `settings.phone_kit` (Quick: always on).

## 4. Studio 2 editor

Route: `app/(app)/settings/online-store/themes/[id]/editor`. Desktop only; under 1024 px it shows "Open the editor on a laptop or desktop".

### Layout

- Top bar: theme name, page switcher (Home, Product, Catalog, Pages ▸ list + New page), undo, redo, device toggle (phone 390 px / desktop), save status, Preview link, Publish.
- Left: theme settings button and the tree (header group, template sections with nested blocks, "+ Add section", footer group). Rows have eye (hide), drag handle and ⋮ (duplicate, remove, rename label).
- Centre: preview iframe.
- Right: settings form generated from the selected item's schema, plus Advanced (colour scheme, CSS class, custom CSS for sections) and Remove/Duplicate.

### Preview bridge

- The iframe loads the real storefront route with `?preview_theme=<id>&token=…&editor=1`, for every preset. The current Studio-only inline preview is removed.
- Editor → iframe: `postMessage({ source: 'kh-studio', type: 'theme:update', theme })` debounced at 150 ms; `select`, `scroll-to`.
- Iframe → editor: `ready`, `hover`, `select`, `add-at` (index between sections).
- Both sides check `event.origin` against the store origin / app origin and ignore everything else.
- In editor mode the storefront wraps each section and block in an outline layer with its name; clicking selects; "+" appears between sections.
- Data-bound sections (product rails etc.) re-fetch through a small client endpoint when their data settings change.

### Editing behaviour

- Drag and drop: `@dnd-kit/core` + `@dnd-kit/sortable`; sections within their group/template, blocks within their section. Limits enforced in the UI and again on the server.
- Add section: modal grouped by category, with thumbnail and presets; only sections allowed for the current template and under their limit.
- Undo/redo: a history stack of whole-theme snapshots (structural sharing), max 100 entries; consecutive edits to the same field within 1 s merge into one entry. Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, Ctrl+Y.
- Autosave: debounced 1 s `PUT /api/settings/online-store/themes/[id]`; optimistic `updated_at` check returns 409 on conflict ("This theme changed in another tab. Reload?"). On network failure: retry banner, unsaved edits kept in `localStorage` keyed by theme id, restored on reload.

### Theme library

`app/(app)/settings/online-store/themes`: live theme card, draft list. Actions: Customise, Preview link (copy 7-day signed URL), Duplicate, Rename, Publish, Delete (drafts only), Version history. "Add theme" picks a preset or blank.

### Version history

Drawer listing publishes (date, author), "Preview" (opens that version read-only via signed token) and "Restore as draft".

### Custom pages

New page modal: title, handle (slug, unique within theme, reserved words blocked), start from Blank / About / Sale / Contact info. Pages appear in the switcher and in the menu link picker. Rendered at `/pages/<handle>`; 404 when the handle is not in the live theme.

### API

- `GET/POST /api/settings/online-store/themes` (list, create from preset or duplicate)
- `GET/PUT/PATCH/DELETE /api/settings/online-store/themes/[id]` (PATCH: rename)
- `POST /api/settings/online-store/themes/[id]/publish`
- `GET /api/settings/online-store/themes/[id]/versions`, `POST .../versions/[vid]/restore`
- `POST /api/settings/online-store/themes/[id]/preview-link`

All require online-store settings permission and the existing plan gate; business from session.

## 5. Storefront rendering

- `lib/store/engine/load-theme.ts` loads the live theme (or a valid preview theme) for the store; falls back to the old renderer when `store_engine` is false.
- `components/store/engine/RenderTemplate.tsx` renders header group → template → footer group inside the store shell, applying preset root class, global CSS variables, colour schemes and scoped CSS (reusing `lib/store/section-css.ts`).
- Data: the renderer collects each section's `data(settings)` requests and resolves them in one batched pass through `lib/store/store-items-query.ts` (product sources), categories and ratings.
- Routes: `/` → home; `/products/[id]` → product; `/catalog`, `/catalog/[category]` → catalog; `/pages/[handle]` → custom page. Existing policy and account routes unchanged.
- SEO: page `<title>`/description from template (custom pages) or product/category data.
- Errors: each section is wrapped in an error boundary. Storefront: renders nothing. Editor mode: red card "This section failed to load: <message>". Unknown types are skipped.

## 6. Migration and rollout

- `lib/store/engine/migrate.ts` converts `business_settings.store_theme` into the first live theme:
  - pack → preset; `studio_sections` → home template (section by section; per-section `custom_css`/`cssClass` kept);
  - Grocery and Khatario home settings (hero, shelves, overlay bands, testimonials, brand story, offers toggles) → matching sections;
  - accent → colour scheme 1; fonts, store-wide custom CSS, phone_kit, announcement settings → theme settings / announcement section.
  - Idempotent: does nothing for a business that already has a live theme.
- `scripts/migrate-store-themes.mjs` runs it; `kh_phase2_test` only until the user approves staging/production.
- Parity report: `scripts/store-engine-parity.mjs` (Playwright, localhost) screenshots each preset's demo store and the test stores at 390 px and 1280 px under the old and new renderer, and writes a side-by-side HTML report to `tmp-qa/engine-parity/`.
- Rollout: `store_engine` on for demo/test stores → all of staging → production after the user reviews the parity report. M6 removes the old renderer, old Studio, `studio-draft` and `store_theme`.

## 7. Testing

- Unit (`tests/lib/store/engine/`): schema sanitiser (unknown keys, clamps, limits, block types, ids); HTML sanitiser (scripts, handlers, `javascript:`, iframe allow-list); colour scheme CSS output; undo history (merge window, limit); `migrate.ts` fixtures for every pack, idempotence; every preset passes its own schemas.
- DB (`tests/db/store-themes*.db.test.ts`, `kh_phase2_test`): one live theme per business; publish swaps roles and writes a version; keeps 30; restore creates a draft; cross-business access denied; preview token expiry and theme binding; size and count limits; 409 on stale `updated_at`.
- E2E (Playwright, localhost): edit → autosave → reload persists; drag reorder; undo/redo; click in preview selects tree item; add section between sections; publish changes storefront; create custom page and open `/pages/<handle>`; parity screenshots.

## 8. Build order

Each milestone ships behind `store_engine`.

1. **M1 Engine core**: tables and theme API; registry and schema sanitiser; server renderer; home template with slideshow, image banner, image with text, rich text, multicolumn, marquee, featured products, product rail, category grid, testimonials, custom HTML, header/footer groups; Studio preset.
2. **M2 Studio 2 editor**: three-pane layout, generated forms, iframe bridge, click-to-select, drag and drop, undo/redo, autosave, publish.
3. **M3 Every page**: product, catalog and custom page templates and their sections; wrap project C components; remaining home sections.
4. **M4 Presets and migration**: Quick, Grocery, Khatario presets with CSS layers; `migrate.ts`; parity report.
5. **M5 Library and history**: theme library page, preview links, version history.
6. **M6 Switch-over**: flag on everywhere (after user approval), remove old renderer and old Studio.

## 9. Integration notes with project C

- Project C components must be prop-driven and theme-agnostic, reading colours from CSS variables; the engine maps `--c-*` scheme variables onto the names they use.
- Engine sections that wrap them: product gallery, product info (variant picker block), related products, recently viewed, reviews, filters + product grid, search suggestions inside the header section.
- Project C does not edit `components/store/admin/theme-studio/*`, `lib/store/studio-*.ts`, `lib/store/store-theme.ts` or `components/store/studio-theme/*`.

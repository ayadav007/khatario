## 2026-10-28: Party pricing brought up to Tally/Busy/Vyapar
- **Asked:** "please complete all the features" from the party pricing review: price levels, quantity slabs, dates, history, discount %, last rate charged, supplier-wise purchase rates, per-unit prices, below-cost warning, sales orders and challans, one buyer price list.
- **Decided:** one server resolver (`lib/pricing/resolve-price.ts`, `POST /api/pricing/resolve`) picks the price for invoices, sales orders and challans: customer price, then the customer's price level (slabs by min qty, then dates), then the item's own price. Discount comes from the customer's item rule, else a category discount, else the level rate, and goes in the line's discount column (challans have none, so it is taken off the rate). Slabs and dates live on price levels; customer prices get dates and discount % but no slabs. A line whose price or discount was typed, loaded from a saved document or agreed on a hub order is never repriced. History is written by the APIs into `price_change_log` (not a trigger, so it records the user). Supplier Hub buyer prices moved into `party_item_prices` for the linked customer; `supplier_buyer_prices` is kept but no longer read. The supplier rate is the last price on a saved purchase bill from that supplier, not a new table. Below-cost compares the pre-GST net price with the item's purchase price.
- **Not done, on purpose:** per-unit prices, because invoice lines cannot be sold in an alternate unit yet (unit is read-only, stock is not converted); that needs selling in alternate units first. Bills made without a screen (recurring, hub conversion, AI agent) keep the prices they carry and are not repriced.

## 2026-10-28: Per-section custom CSS in Studio
- **Asked:** let merchants style one section with custom CSS: section hooks, scoped CSS in the Advanced tab, store-wide CSS moved into Studio with live preview, and a class reference.

Each section has "CSS class names" (up to 3 plain tokens) and "CSS for this section only" (3,000 chars) in Advanced. `lib/store/section-css.ts` rebuilds that CSS rule by rule: every selector is prefixed with `#section-{id}`, `&`/`:scope`/`body`/`html`/`:root`/`.st-root` mean the section box, @media/@supports/@container recurse, @keyframes are copied, other at-rules, comments and every `<` are dropped, and the output is always brace-balanced, so it can't leak out of its section or close the `<style>` tag. Store-wide CSS (`theme.custom_css`) moved to a new Studio page "Custom CSS" (`pages.customCss`; drafts saved before fall back to the theme's); the editor previews it inside `@scope (.ks-root .store)` so it can't restyle the editor, while the live store keeps applying it unscoped as before. The Appearance settings box now links to Studio. A collapsible reference lists the stable class names per section, the colour variables and click-to-add examples. Colour variables are set inline on the store root, so they must be overridden on `.st-root .st-sec`, not `.st-root`; the examples say so.
